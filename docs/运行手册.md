# AeroMind Sim 运行手册

本文面向第一次下载仓库的开发者，说明依赖、安装、运行、验证和发布流程。命令默认在仓库根目录执行。项目用于 ROS 2、Gazebo 和 ArduPilot SITL 的软件验证，不能替代实机调试、飞行前检查或比赛验收。

需要修改源码、模型或测试时，另见[开发环境与维护流程](development.md)。

## 1. 支持环境

| 项目 | 版本或要求 |
| --- | --- |
| 操作系统 | Ubuntu 22.04，amd64 |
| ROS | ROS 2 Humble |
| 仿真器 | Gazebo Sim 7 |
| Python | 3.10 |
| 磁盘 | 建议至少 20 GB 可用空间；Docker 构建另有镜像层开销 |
| 网络 | 安装阶段需要访问 Ubuntu、ROS 和 ArduPilot 上游源 |
| 权限 | `make setup` 需要 `sudo` 安装系统包 |
| 图形 | 支持 OpenGL 4.x 的桌面环境；无硬件 OpenGL 时可软件渲染 |

推荐使用有独立显卡的桌面或工作站。软件渲染只适合排查和低速验证，不适合评估实时性能。

仓库不包含本机 Python 虚拟环境、ROS 工作空间、ArduPilot 二进制、地图或运行日志；这些内容由安装和构建流程写到外部私有目录。

## 2. 安装和构建

```bash
git clone https://github.com/wang3537248429/uav-ugv-cooperation-sim.git
cd uav-ugv-cooperation-sim
bash tools/setup_ubuntu_22_04.sh
./start.sh --check
```

先退出 Conda / Python 虚拟环境。安装脚本（已有 `make` 时也可运行 `make setup`）会：

1. 安装 ROS、Gazebo、编译工具和运行时依赖；
2. 在 `${XDG_CACHE_HOME:-$HOME/.cache}/aeromind-sim/` 创建运行工作区；
3. 获取并编译 ArduPilot SITL；
4. 编译本项目的 ROS 包，并检查节点导入、ArUco、cv_bridge、Gazebo 版本和场景资源。

已经准备好系统依赖，只需要重新构建源码时执行：

```bash
make build
```

源码移动或仓库目录名改变后，检查 `COMPETITION_LOCAL_DIR` 是否仍指向正确的外部目录，然后重新执行 `make build`。不要直接编辑私有目录中的安装副本。

下载源码 ZIP 时，先解压进入源码根目录，再执行同样的安装脚本和 `bash start.sh --check`。使用 `bash` 调用脚本不依赖解压工具保留执行权限。安装脚本按固定提交获取 ArduPilot，并应用仓库中的两个补丁；不需要原作者的依赖目录、地图或构建缓存。安装后可以运行 `make check` 和 `make test-all` 验证环境。

需要统一环境的无头运行时，可按 [README 的 Docker 步骤](../README.md#docker-无头运行)构建镜像。CI 使用同一 Dockerfile，从空白 Ubuntu 安装并完成建图和地图定位任务。

## 3. 私有目录和环境变量

默认目录是 `${XDG_CACHE_HOME:-$HOME/.cache}/aeromind-sim/`。可以在构建和运行前设置绝对路径：

```bash
export COMPETITION_LOCAL_DIR=/srv/aeromind-sim-private
make build
./start.sh --check
```

该目录不能位于源码仓库内。主要内容如下：

| 子目录 | 内容 |
| --- | --- |
| `build/` | colcon 编译中间文件 |
| `install/` | ROS 安装空间 |
| `logs/` | colcon 和 ROS 日志 |
| `dependencies/` | ArduPilot 等外部依赖 |
| `maps/` | `arena.npz`、`.pcd` 等地图 |
| `artifacts/` | smoke 和 GUI 回归日志 |
| `releases/` | 发布源码包 |

删除该目录会同时删除编译结果、依赖和地图；重新运行 `make setup` 可恢复软件环境，地图需要重新生成。需要保留的自建地图或本地标定文件应另行保存。多个源码副本做独立验证时，用不同的 `COMPETITION_LOCAL_DIR` 隔离各自的构建与地图。

`tools/workspace_env.sh`、`tools/activate.sh` 和 `start.sh` 使用同一套目录规则。需要运行 `ros2` 命令时先执行：

```bash
source tools/activate.sh
```

可选环境变量：

| 变量 | 默认值 | 用途 |
| --- | --- | --- |
| `COMPETITION_LOCAL_DIR` | `${XDG_CACHE_HOME:-$HOME/.cache}/aeromind-sim` | 外部构建、依赖、地图和日志目录 |
| `SITL_WORKDIR` | `$COMPETITION_LOCAL_DIR/sitl` | ArduPilot SITL 工作目录 |
| `ARDUCOPTER_BIN` | `$COMPETITION_LOCAL_DIR/dependencies/ardupilot/build/sitl/bin/arducopter` | SITL 可执行文件 |
| `ROS_DISTRO` | `humble` | ROS 安装目录和测试环境 |
| `PYTHON` | `python3` | Makefile 使用的 Python 命令 |
| `BUILD_JOBS` | `2` | 安装时 SITL 和 ROS 构建的并行数，可按内存调整 |
| `SMOKE_TIMEOUT` | `600` | 每轮 smoke 的超时秒数 |
| `SMOKE_VISUAL` | `0` | 设为 `1` 时打开 Gazebo、RViz 和相机，结束后自动清理进程 |
| `SMOKE_ARGS` | 空 | 传给 `tools/run_headless_smoke.sh` 的参数 |
| `RUN_ARGS` | 空 | 传给 `start.sh` 的参数 |

例如使用自定义 SITL 构建：

```bash
export COMPETITION_LOCAL_DIR=/srv/aeromind-sim-private
export ARDUCOPTER_BIN=/opt/ardupilot/build/sitl/bin/arducopter
make build
./start.sh --check
```

## 4. 启动模式

没有地图时先建图：

```bash
./start.sh --mapping
```

结束建图并停止仿真后，加载冻结地图：

```bash
./start.sh --localize
```

如果默认地图路径不适用，可以显式指定：

```bash
./start.sh --localize --map "$COMPETITION_LOCAL_DIR/maps/arena.npz"
```

常用参数：

```bash
./start.sh --check             # 只检查环境和 launch 参数
./start.sh --no-camera         # Gazebo + RViz2，不打开独立相机窗口
./start.sh --headless          # 不打开 Gazebo 和 RViz2
./start.sh --manual             # 等待 /mission/start
./start.sh --software-render    # 强制软件渲染
./start.sh --build              # 启动前先重新构建
./start.sh --gcs 14550          # 转发 MAVLink 到本机 UDP 14550
```

默认任务会自动开始。手动模式需要另开终端：

```bash
source tools/activate.sh
ros2 topic pub /mission/start std_msgs/msg/Bool '{data: true}' --once
```

点云模式完整任务通常需要约三分钟，实际时间取决于 CPU、GPU 和 Gazebo 实时率。运行期间不要启动第二个本项目实例；启动脚本会通过 `${XDG_RUNTIME_DIR}/competition_ws-$(id -u)/simulation.lock` 保护固定端口和仿真资源。

## 5. 地图、航线和参数

地图文件由建图模式保存到：

- `$COMPETITION_LOCAL_DIR/maps/arena.npz`：定位使用的带元数据地图；
- `$COMPETITION_LOCAL_DIR/maps/arena.pcd`：通用 XYZ 点云导出。

建图模式不会覆盖已有地图。另存一份地图：

```bash
source tools/activate.sh
./start.sh --mapping --map "$COMPETITION_LOCAL_DIR/maps/arena-v2.npz"
./start.sh --localize --map "$COMPETITION_LOCAL_DIR/maps/arena-v2.npz"
```

室内航点在 `uav_map` 中使用米制 `[x, y, z]`，X 向前、Y 向左、Z 向上。复制后再编辑，避免修改仓库中的默认路线：

```bash
source tools/activate.sh
cp src/ap_navigation/config/competition_waypoints.yaml \
  "$COMPETITION_LOCAL_DIR/route.local.yaml"
ros2 run ap_navigation map_tool "$COMPETITION_LOCAL_DIR/maps/arena.npz" \
  --route "$COMPETITION_LOCAL_DIR/route.local.yaml" --clearance 0.18
./start.sh --localize --manual \
  waypoint_file:="$COMPETITION_LOCAL_DIR/route.local.yaml"
```

雷达定位和飞行参数也建议复制到私有目录后覆盖：

```bash
cp src/ap_navigation/config/navigation.yaml \
  "$COMPETITION_LOCAL_DIR/navigation.local.yaml"
cp src/ap_simulation/config/pointcloud_flight.yaml \
  "$COMPETITION_LOCAL_DIR/flight.local.yaml"
./start.sh --localize --manual \
  navigation_params:="$COMPETITION_LOCAL_DIR/navigation.local.yaml" \
  flight_profile:="$COMPETITION_LOCAL_DIR/flight.local.yaml"
```

这些节点的大部分参数在启动时读取；修改文件后需要重启任务。航点工具只检查已观测地图的净空，不能替代真实机体、针具、定位误差和未知障碍物的安全余量。

## 6. Mid-360、RViz 和地面站

仿真雷达按 Mid-360 的主要视场、频率、量程和噪声量级建模，输出 `/navigation/lidar/points`。Gazebo 的 `gpu_lidar` 是规则栅格近似，不复现真实 Livox 的非重复扫描。实机使用 `livox_ros_driver2` 时，应将 `CustomMsg` 转为 `sensor_msgs/PointCloud2`，并把实测外参写入本地导航参数。

RViz2 固定坐标系为 `uav_map`，用于查看地图、注册点云、定位轨迹、航点、ExternalNav 和场地标记。它目前是显示工具，没有鼠标拖拽航线编辑器。

连接 Mission Planner 或 QGroundControl：

```bash
./start.sh --localize --gcs 14550
```

在地面站中连接 UDP `14550`。该连接用于查看参数、模式和日志；ROS 任务状态机仍负责本仿真的自动任务。不要让地面站、ROS 节点和遥控器同时发送冲突的 GUIDED、解锁或降落命令。

室内使用 `uav_map` 米制坐标。室外需要 WGS84/GPS 或 RTK 参考，先建立 `earth -> map` 地理锚点，再切换 EKF 源。当前仓库没有自动的室内/室外定位源切换器，不能把仿真默认原点直接用于实机现场坐标。

## 7. 验证流程

修改飞行状态机、制导、传感器、模型或导航代码后，按顺序运行：

```bash
make check
make build
make test-all
make smoke
```

`make check` 包含代码风格、独立测试、场景尺寸和公开内容检查；`make test-all` 还包含 ROS 回归测试；`make smoke` 执行一轮完整无图形任务。成功标准是任务状态机进入 `COMPLETE`，且日志中没有 `ABORT`、`FAILSAFE`、`Traceback` 或节点崩溃。

验证建图和冻结地图定位的完整流程：

```bash
SMOKE_VISUAL=1 make smoke-mapping
```

该命令依次运行建图、停止、重新启动、加载冻结地图和定位飞行两轮。所有日志写入 `$COMPETITION_LOCAL_DIR/artifacts/`。完整仿真期间不要运行其他实例。

## 8. 停止、排错和清理

正常停止使用当前终端的 `Ctrl+C`。如果启动命令通过 `setsid` 放入后台，停止整个进程组：

```bash
kill -TERM -- -LAUNCH_PID
sleep 4
kill -KILL -- -LAUNCH_PID 2>/dev/null || true
```

确认没有残留项目进程和锁：

```bash
pgrep -af 'gz sim|rviz2|camera_view|arducopter.*AeroMind|uav_mission_state_machine|pointcloud_navigation|ap_mavlink_bridge' || true
lsof "$XDG_RUNTIME_DIR/competition_ws-$(id -u)/simulation.lock" 2>/dev/null || true
```

排错顺序：

1. 运行 `./start.sh --check`，确认 ROS、Gazebo、SITL 可执行文件和 launch 参数；
2. 检查 `$COMPETITION_LOCAL_DIR/artifacts/` 的最新日志；
3. 确认没有其他实例占用 9002、5760 或仿真锁；
4. 图形环境异常时尝试 `--no-camera` 或 `--headless --software-render`；
5. 修改源码后重新运行 `make build`，不要使用旧的私有安装副本。

## 9. 发布前检查

只发布 Git 仓库中的源码、测试、场景资源和文档。不要发布私有目录、构建目录、地图、日志、视频、本机密钥或依赖缓存：

```bash
git add -A
git diff --cached --stat
python3 tools/check_open_source_hygiene.py --staged
make check
make release
```

检查 staged diff 是否包含用户名、绝对路径、内网地址、令牌、SSH 密钥、序列号或本机生成文件。`make release` 会在私有目录生成不含 `.git` 的 `releases/aeromind-sim-source.zip`。
