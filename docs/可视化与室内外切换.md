# 可视化、Mid-360 与室内外切换

本项目使用三个界面：

- Gazebo：查看物理世界、机体和相机；
- RViz2：查看点云地图、定位轨迹、航点和场地标记；
- Mission Planner（MP）或 QGroundControl（QGC）：查看 ArduPilot 状态、参数和日志，并编辑有 GPS 地理参考的室外任务。

MP/QGC 不直接读取项目的 `uav_map` 米制航点。

## 启动可视化仿真

首次采集地图：

```bash
./start.sh --mapping --manual
```

另一个终端启动任务：

```bash
source tools/activate.sh
ros2 topic pub /mission/start std_msgs/msg/Bool '{data: true}' --once
```

已有地图时运行定位：

```bash
./start.sh --localize --manual
```

指定地图并关闭独立相机窗口：

```bash
./start.sh --localize \
  --map "$COMPETITION_LOCAL_DIR/maps/arena.npz" \
  --manual --no-camera
```

RViz2 的固定坐标系是 `uav_map`。默认显示以下话题：

- `/navigation/map`：正在建立或已保存的点云地图；
- `/navigation/cloud_registered`：当前注册点云；
- `/navigation/path`：点云定位轨迹；
- `/mission/waypoints`：UAV 航点；
- `/ap/external_nav/vision_pose`：发送到飞控的 ExternalNav 位姿；
- 场地 Marker 和 UGV 预设路线。

RViz2 当前只负责显示和诊断，没有鼠标选点或拖拽航线功能。

## 编辑室内航线和参数

室内航点使用 `uav_map` 米制坐标：X 向前、Y 向左、Z 向上。先复制默认文件，再在私有目录编辑：

```bash
source tools/activate.sh
cp src/ap_navigation/config/competition_waypoints.yaml \
  "$COMPETITION_LOCAL_DIR/route.local.yaml"
```

编辑后检查地图净空，再重启任务节点：

```bash
ros2 run ap_navigation map_tool "$COMPETITION_LOCAL_DIR/maps/arena.npz" \
  --route "$COMPETITION_LOCAL_DIR/route.local.yaml" --clearance 0.18
./start.sh --localize --manual \
  waypoint_file:="$COMPETITION_LOCAL_DIR/route.local.yaml"
```

航点文件只改变 UAV 路线，不会移动场景物体或 UGV 路线。任务标签和航点顺序仍由 `route_io.py` 校验。

复制参数文件后再调整导航和飞行控制：

```bash
cp src/ap_navigation/config/navigation.yaml \
  "$COMPETITION_LOCAL_DIR/navigation.local.yaml"
cp src/ap_simulation/config/pointcloud_flight.yaml \
  "$COMPETITION_LOCAL_DIR/flight.local.yaml"
./start.sh --localize --manual \
  navigation_params:="$COMPETITION_LOCAL_DIR/navigation.local.yaml" \
  flight_profile:="$COMPETITION_LOCAL_DIR/flight.local.yaml"
```

参数在节点启动时读取。修改文件后必须重启；运行中的 `ros2 param set` 不保证改变定位器或任务状态机的行为。

## Mid-360 仿真和实机接入

仿真雷达保留 Mid-360 的主要约束：10 Hz、360° 水平视场、约 -7° 到 52° 的垂直视场、40 m 名义量程和约 200 k 点/秒级别的点云。Gazebo `gpu_lidar` 仍是规则栅格，不是 Livox 的真实非重复扫描；它用于验证接口、点云处理和定位链路。

相关配置：

- `src/ap_simulation/models/competition_x500/model.sdf.in`：传感器模型；
- `src/ap_navigation/config/navigation.yaml`：话题、外参、体素和 ICP 参数；
- `src/ap_simulation/launch/sim_all.launch.py`：Gazebo 到 ROS 的 `PointCloud2` 桥接。

规范输入话题为 `/navigation/lidar/points`，传感器坐标系为 `drone/base_link/navigation_lidar`。实机使用 `livox_ros_driver2` 时，先将 `/livox/lidar` 的 Livox `CustomMsg` 转成 `sensor_msgs/PointCloud2`，再接入该话题。不要直接把 `CustomMsg` 交给 `pointcloud_navigation`。

实机必须用测量值替换 `sensor_xyz_rpy`，并校验时间同步、坐标轴和外参。仓库默认值只是机体顶部中心、Z=0.15 m 的仿真假设。

## 连接 Mission Planner/QGC

启动 MAVLink UDP 转发：

```bash
./start.sh --localize --gcs 14550
```

在同一台电脑的 MP/QGC 中连接 UDP `14550`。地面站可用于查看飞控状态、读写参数、切换模式和查看日志；ROS 任务状态机仍负责自动任务。不要让地面站、ROS 节点和遥控器同时发送冲突的 GUIDED、解锁或降落命令。

地面站位于另一台电脑时，可以传递完整的输出地址：

```bash
./start.sh --localize --gcs 14550 \
  gcs_output_url:=udpout:ground-station-host:14550
```

网络上只开放所需的 MAVLink UDP 端口。室内 `uav_map` 航线仍通过 YAML 或专用地图工具维护；MP/QGC 的 Plan 航线用于已有 WGS84/GPS 参考的室外任务。

## 室内无 GPS 与室外 GPS

室内链路如下：

```text
Mid-360 点云
  -> ICP 地图定位
  -> /ap/external_nav/vision_pose
  -> ArduPilot EKF3 ExternalNav
  -> GUIDED 航点
```

仿真配置使用 `GPS_TYPE=0`，EKF3 的位置、速度和航向源使用 ExternalNav（值 6）。这条链路不提供 GPS，也不能替代室外导航配置。

室外建议使用 RTK-GNSS，并保留以下坐标层次：

```text
earth (WGS84) -> map (任务地图) -> odom (连续里程计) -> base_link
```

`map` 中的路线仍用米制坐标；GPS/RTK 只负责建立 `earth -> map` 的地理锚点。不要把 `[x, y, z]` 直接当成经纬度，也不要在飞行中把有跳变的 GPS 和点云位姿同时交给 EKF。

切换应在降落或安全悬停时完成：停止任务，确认 GPS/RTK 固定和 ExternalNav 质量，设置正确的 EKF origin/home，切换来源后观察数秒稳定性。当前仓库没有自动的室内/室外定位源复用器，`bridge_config.py` 的默认原点不能直接用于现场坐标。

## UAV 与 UGV 共图

仿真提供：

- `/sim/ugv_pose_ned`：UGV 位姿；
- `/mission/ugv_progress`：路线进度；
- `/mission/ugv_state`：UGV 状态。

RViz2 当前显示 UGV 预设路线，不显示独立的动态 UGV TF/Path。实机协同建议让两台设备发布到同一个 `map`：

- UAV：`map -> odom_uav -> uav/base_link`；
- UGV：`map -> odom_ugv -> ugv/base_link`；
- UAV 航点和 UGV Nav2 目标统一使用 `map` 坐标；
- 协同节点集中完成一次 NED/ENU/FLU 转换，再分别发布飞控 setpoint 和 Nav2 goal。

这样室内使用同一张 Mid-360 地图，室外只更新 `earth -> map` 锚点，路线和协同接口可以保持一致。动态 UGV TF/Path 和交互式 UAV/UGV 航线编辑仍需单独实现。
